# 3Dキャラ制作の掟（設計書18。対決ビュー・守備ビューの3Dキャラの作業で常に従う）

- **3Dのコードを触ったら EditMode テストを回す**（MCP `run_tests` mode=EditMode、または Test Runner。約2秒）。
  CI には Unity のライセンスが無く回らない。`DuelStageGuardTests` は「絵でしか気づけない」実害の見張りで、
  どれも実装を1つずつ壊して赤くなることを確かめてある。新しい実害を見つけたら、段落を足す前に検査にできないか考え、
  足した検査は**一度実装を壊して赤くなるのを確かめてから**残す（壊しても緑の検査は誤った安心を生む）
- URPは品質設定（Quality）ごとに別RenderPipelineAssetを持つ。Render Feature追加・シェーダ設定は
  Graphics / Quality 両方のRenderPipelineAsset整合を確認してから行う（design-18 §2）
- 左打者・左投手は素体GOでなく**x=0面の無回転な鏡映親ノード**の `localScale.x=-1` で作る
  （スケールは回転より内側で効くため、素体自身を反転するとヨー付きの投手で前後の鏡になる）。
  負スケール祖先の下では ①SMRバウンズが狂い寄りでメッシュが消える ②剛体メッシュは巻き順が
  裏返り完全不可視 ③Humanoid Foot IK が両足を「鏡映されない側」のゴールへ引っ張り脚が頭の高さへ
  折り畳まれる（鏡映面 x=0 上に立つ投手は発症しない＝役割ごとに絵で確認）、の3つが**絵でしか
  気づけない形**で起きる＝ミラー中だけ固定バウンズ（±5m巨大箱。バインド箱の拡大は空間違いでダメ）＋
  両面描画へ切り替え、**グラフの評価は鏡映を外した空間で行う**（`DuelStageRig.EvaluateGraph`＝評価の間だけ
  鏡映親のスケールを恒等へ戻す。負スケールのまま評価するとルートモーションが向きごとに裏返り、左投手が
  本塁と逆へ下がりながら投げていた＝issue #914。Foot IK もこれで右と同じ式で解けるのでミラー中もON。design-18 §3.4。
  旧「Mirror ON時はアタッチ先ボーン反転」は本方式では不要になり廃止）
- 購入モーションFBX（AA Basic Baseball等）**および購入素体FBX**（School Baseball Player 0001）を
  公開リポジトリに含めない（再配布NG。design-18 §3.1 / §3.2.1）
- 素体はバインドポーズの顔向きが個体ごとに違う（UBC・U2＝-Z／購入素体＝+Z）。取り違えると帽子が後ろ被りになる。
  検査: `DuelStageGuardTests.*_Faces*`（捕手・投手・球審）。打者は首の補正が隠すので、素体を足したら絵でも確かめる（design-18 §3.2.1）
- AI生成メッシュ（Meshy画像→3D）の出力姿勢は「正面 -Y・上 +Z」で一定。装着正位への変換は
  `DuelGearMeshes.CanonicalizeMeshy` に集約し、資産ごとに向きを推測しない（design-18 §3.3.1）。
  ただし「正面」は**元写真に写っていた面**（背面写真から作ると中継視点で甲が見え続ける＝2026-11-08 実害）。
  **Tripo（画像→3D）の出力姿勢は生成物ごとに違う**ので、デシメート時に rot 引数で Meshy と同じ姿勢へ回してから
  取り込む（design-18 §3.3.2）
- **装備メッシュは1サブメッシュで描く**（2つ目以降は黙って描かれない。`DuelGearMeshes.MergeSubmeshes`）。
  検査: `DuelStageGuardTests.MergeSubmeshes_JoinsAllTrianglesIntoOne` / `GearMeshes_AreSingleSubmesh`（design-18 §3.3.2）
- グラブ・ミットをはめた手は描かない（`DuelStageRig.HideGloveHand`＝体メッシュから手の三角形を抜く。骨は触らない）。
  検査: `DuelStageGuardTests.*GloveHandIsHidden` / `Catcher_MittHandIsHidden`（design-18 §3.3.2）
- 生成メッシュはUnityに取り込む前に必ずデシメートする（50万tri級を取り込ませるとエディタが固まる）。
  形の確認は `tools/aigear-preview.py`（Blender単体の6面図）。Decimate(Collapse) は穴を保存するので、
  穴の多い生成物は voxel remesh を前置する。ただし細バーは溶けるので捕手マスクには使わない（design-18 §3.3.1）
- デシメートの成否は**目標三角形数でなく絵で判定する**。下限の1.5倍でも形が壊れる入力がある
  （捕手ミットは下限5,261に対し8,000triで崩壊）。「目標どおり落ちた＝成功」ではない（design-18 §3.3.1）
- 装備は「実装した」と「全員に配った」が別。投手は2026-07-29までグラブを持っていなかった
  （装着処理が捕手専用で、投手へ配る呼び出しが無かった）。役割ごとに1人ずつ絵で確かめる（design-18 §3.3）
- 手に持たせる道具の位置は手ボーン（＝**手首**）でなく手の中心（手首→指先の中点）。向きはボーン軸でも
  視線方向でもなく**手の実測**で組む（縦軸=手首→中指付け根／正面=掌の法線。符号だけ視線で決める）。
  薄い道具の面を視線に固定すると、掌が相手を向かないポーズで手が板を突き抜ける（design-18 §3.3.1）
- 装着結果は目測でなく実測で確かめる（`GloveDiagForCapture` / `PreviewProbeForCapture`）。
  カメラの狙い外しと未装着は絵では区別できない。**寄りの絵は装備自身の軸から撮る**＝
  斜めの絵では手と道具の前後・左右が分離できず「ずれている」のか「そう見えるだけ」か判定できない（design-18 §3.3）
- 3Dビューの構図は画角[度]でなく**縦に収めたい実寸[m]**で指定する。カメラは水平画角を保つので、
  画角固定だと欄の縦横比が変わった瞬間に頭と足が切れる。逆に縦横比を固定して中央寄せしても
  被写体は大きくならない（背丈はRTの高さだけで決まる）＝余白の帯が出るだけ（design-18 §3.5.1）
- `DuelCalibration` に項目を足すときは `CurrentVersion` を上げ、`Upgrade` には**その版で増えた項目だけ**を
  埋めるブロックを足す（一括で既定へ戻すと調整済みJSONが白紙に戻る。design-18 §8.1）
- チームカラー→マテリアル流し込みは tokens.uss と同型のパターンとして部品辞書に登録する（design-18 §3.5）
- 選手（投手・打者・捕手）は**購入素体**、球審だけ**U2生成素体**＝素体2系統の併存を許容する
  （design-18 §3.2.1。購入素体が無い環境では黙ってU2へ落ちるので、絵が違ったらまず実在を疑う）
- U2素体（球審・フォールバック）のユニフォームは素体を着衣化した生成メッシュ。領域区分け・着衣・痩せは
  `DuelUniformMeshBuilder`（Unity Editor C#）＋`DuelUniformBaker` で生成し、手作業でUV・頂点を触らない
  （design-18 §3.5.2。旧bpy案は2026-07-28に廃止）。購入素体は完成メッシュなので
  `DuelVendorRegionBaker` で領域IDを後付けにUV1へ焼く（design-18 §3.2.1）
- 縦縞はテクスチャに焼かず、シェーダプロパティ（ON/OFF・縞色・周波数）で手続き生成する（design-18 §3.5.3）
- 購入素体の領域は「メッシュ＝1領域」で足りない所がある。ベルトは `Pants` メッシュの中の帯で、
  塗り分けないと白ズボンに白いベルトが乗るだけになる。テクスチャの色で三角形単位に振り分ける
  （`DuelVendorRegionBaker`。UV島が分かれていれば頂点は割れているので領域またぎは0になる。design-18 §3.5.1b）
- **配列で渡す色（`_RegionColors` 等）は自分でガンマ→リニア変換する**（`SetColorArray` は素通し＝黒が中間グレーになる）。
  固定の黒はパレット表の #23242A（赤に寄せると臙脂に落ちる）。検査: `DuelStageGuardTests.RegionColors_ArePassedInLinearSpace`（design-18 §3.5.1）
- 素体の形を変えるベイク（袖の張り出し等）で **`RecalculateNormals` を呼ばない**。非溶接メッシュでは
  UV島の境目が全部ハードエッジになり体が面取りされて見える。腕・脚の軸は**ボーンのバインドポーズ**から
  取る（素体はAポーズでメッシュ座標から軸を推測すると胴を巻き込む。design-18 §3.5.1b）
- 手続き模様（縦縞）を**スキンメッシュの頂点位置で刻まない**。頂点シェーダが受け取るのは変形後の座標で、
  模様が空間に固定され「体が模様の中を通り抜ける」。静止座標をベイクして刻む。線の太さは比率でなく実寸、
  被覆率は解析的に（閾値比較だけだと1画素未満の線が点線に割れる）。3点揃って初めて縞に見える（design-18 §3.5.3）
- チームカラーは `data/team-colors.yaml` のパレット表＋校IDの決定論選択（乱数不使用・`string.GetHashCode` 禁止）。
  試合中不変なので観測データ `MatchLiveSnapshot` に載せず、`LivePlayerMatch`→`LiveMatchRequest` の静的経路へ通す
  （design-18 §3.5.1）
- キャラのポーズ更新は時間量子化（12fps相当・専用コンポーネントで制御）。**ボール・カメラはフルレート維持**。
  量子化対象を混同しない（design-18 §4.5-②）
- 投球の絵は**着弾点＝判定に使われた実着弾位置**（`PitchRecord.LocationX/Y`）で描く。観測用フル弾道
  `PitchTrajectory` は**コースを入力に取らない**（まっすぐ投げた球の落ち方だけ）ので、位置列をそのまま
  再生すると判定と食い違う＝弾道から使うのは飛翔時間と誘発変化量だけ。曲がりの式は engine の
  `PitchFlightPath` に集約し、Unity側で積分し直さない。左右は engine も対決ビューも **+x=一塁側**で
  変換不要（`PitchSpec.AimAzimuthDeg` のコメント「+で三塁側」は逆なので信用しない。design-18 §4.5-③）。
  **例外は「打つ球」だけ**＝実物の接触は本塁の上でなく前で起きるので、判定面より `ContactAheadM`
  だけ投手側で当てる。①投球の描画が終わる点 ②打球の開始点 ③バットの狙点 は**必ず1つの定数**から
  出す（別々に持つとずれる）。判定は判定面のままなので帯は動かない（design-18 §4.5-⑨）
- 弾道を「両端固定＋弦からの逸れ」で描くときの**逸れの符号**に注意。球は**弦より上**を通る
  （上に凸）。逆にすると全球が前半急降下・後半水平〜上昇して**あらゆる球がホップして見える**
  （2026-07-30 実害）。逸れは**加速度と逆向き**に膨らむ＝ホップが強いほど弦に寄って平坦になるのが正しい。
  切り分けは落差の推移（正しければ落差が広がる）。検証は「無回転＝重力のみの自由飛行の厳密解と一致」で固定する
- モーキャップクリップの内部緩急を改変しない。同期は再生開始時刻のアンカー逆算（AnimationEvent基準）で行い、
  捕球・ミートの端数合わせはEvent直前の短時間IKで吸収する（design-18 §4.5 / §7-2）
- アンカーは「クリップの頭出し」だけでは合わない。**捕球のように球より遅い瞬間はクリップ開始を後ろへ
  ずらす予約が要る**（`Mathf.Max(0, moment - flight)` は負を潰して常にリリース直後に捕る＝2026-07-30 実害）。
  さらに**捕球の瞬間の定義はクリップごとに違う**（ミットを構えて待つクリップは「引き始め」、
  ミットを運ぶクリップは「運び終わり」）＝一律の式で出さず実測表に焼く（design-18 §4.5-③）
- ポーズ補正IKの重みは**当てたい瞬間の1コマ以上前に1へ寄せ切る**。ポーズは12fpsなので、瞬間ちょうどで
  1になる台形だと絵に出る直前のコマが重み0.7＝寄り切らない（実測0.199m残る）。当てるのは
  **ポーズを評価した直後だけ**（重み<1は今の位置からの補間なので二度当てると寄りすぎる）。
  駆動はクリップ内時刻でなく**球の時計**（クリップ差し替えのコマで飛ばないため。design-18 §4.5-③）
- **「特定のコマでだけ起きる副作用」をポーズ更新に書かない**。ポーズは12fpsの格子なので、
  狙ったコマに格子が乗るかは**頭出し位置と狙点の位相**次第で、乗らない結果だけ黙って壊れる
  （実測: 振り抜きの起点を「進みが1に届いたコマ」で焼く実装は、**空振りだけ**一度も焼かれず
  バットが構えの向きのまま固まった）。焼く値が幾何で決まるなら毎コマ焼く（design-18 §4.5-⑩）
- 収録の要らない芝居は「クリップの尺」でなく**その部位の補正窓**で消す（首振り等）。尺で消すと
  欲しい動きまで落ち、部位ごとに始まる時刻が違うので必ずどれかが残る。体幹の動き（構えへ戻る等）
  だけは尺で切るしかないが、**打ち切りには必ず据え置きを添える**＝据え置きが無いと打ち切った
  瞬間に待機へ戻る（実測: インプレーだけ「打った0.36秒後に構えている打者」が映っていた。
  1結果でしか試さないと見逃す。design-18 §4.5-⑬/⑭）
- 道具を球に当てる時刻は「道具が届く距離」だけで決めない。**手が狙点と同じ深さに来る時刻**で採る。
  距離だけで採ると手が狙点の斜め手前に居る瞬間を選んでしまい、芯を球に乗せた形が
  **腕に対して折り返る（こねる）**。立ち位置も同時に解く（その時刻の手→狙点＝道具の長さ）＝
  **立ち位置は絵の好みで決めない**。ここを外すと軌道側をいくら直しても直らない（design-18 §4.5-⑪）
- 手で持つ道具の向きを**収録の手から採ってよい区間は無い**。当てにいく区間は当然として、
  振り抜いた後の惰性区間ですら、フォロースルーの手首は1コマで175°回りバットが足元を向く。
  惰性は**胸の中で剛体**にする（体が回るぶんだけ回る＝実物のフォロースルー。design-18 §4.5-⑩）
- Edit modeで骨を実測するプローブは `Animator.cullingMode = AlwaysAnimate` を必ず設定する。
  既定のままだと画面外扱いで**骨が書き戻されず、ルートモーションだけが効く**。しゃがみクリップが
  「立ったまま」に見えるだけで例外もテスト失敗も出ないので、クリップの中身を誤って結論づける
  （2026-07-30 実害。既存の正解パスは `DuelMotionSpike.SpawnBody`）
- ルートモーション付きクリップのクロスフェード中は `applyRootMotion` を切る。`Pause` した退場側でも
  ミキサーが流すのは**両入力の混合ルート姿勢の差分**なので、切らないと向きが231°飛ぶ。また積分の刻み幅
  （12fps再生 vs 60fpsシーク）で食い違うのは**位置だけで向きは一致する**＝リリース再同期は向きを追従させ、
  位置を据え置く。この手のずれは絵では「向きが少し変」としか見えず切り分け不能なので、
  `DuelRootMotionProbe` / `PitcherDiagForCapture` の実測で判定する（design-18 §7-2）
