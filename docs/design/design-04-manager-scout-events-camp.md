決定事項の反映: 転任=**強制転任あり（元祖忠実）** / 指導力=**分野別** / 新入生=**ハイブリッド**

## 1. 監督メタ

### 1.1 監督能力（分野別・キャリアを通じて持ち越す唯一の資産）
| 能力 | 効果 |
|---|---|
| 打撃指導 | 打撃系練習の効率係数 |
| 投手指導 | 投手系練習の効率係数、投手起用のスタミナ見積り精度 |
| 守備走塁指導 | 守備・走塁系練習の効率係数 |
| 育成眼 | 個別指導「見極め」の精度、新入生の隠しパラメータ開示精度 |
| 采配 | 自動進行時の配球・作戦の質、相手の作戦察知 |

- **成長は2階建て**（プレイヤーが意識して管理する対象にはしない）:
  1. **試合経験でゆるやかに自然増**: 練習試合・公式戦をこなすと分野別能力が少しずつ上がる
     （元祖の「練習試合で指導力が上がる」を踏襲）。格上相手・大舞台ほど得られる経験がやや大きい。
     プレイヤーが積極的に伸ばす操作は不要 ＝ 気づいたら練れている
  2. **節目イベントで大きく伸びる**（下記1.1b）: キャリアの物語の起伏として、特定能力がぐっと動く
- 設計書02の練習式の指導力項を、この分野別係数に置き換える

### 1.1b 監督成長イベント（例）
設計書03のイベントシステムに監督成長フラグを持たせ、条件成立で発生。効果はその場の能力上昇。
- **名将との練習試合**: 甲子園常連校などと対戦すると、采配 or 該当分野の指導力が上昇（教えを乞う）
- **大敗からの学び**: 大差negative の敗戦後、悔しさイベント → 弱点分野の指導力が上昇
- **指導者講習会**: オフ（冬）に参加を選ぶと指導力が上昇（費用・時間とのトレードオフ）
- **プロOBの訪問**（設計書 §3.1のイベント連動）: 教え子や縁のあるOBが来訪 → 采配・育成眼が上昇
- **甲子園経験**: 甲子園の舞台を踏むと采配が大きく上昇（頂点の空気を知る）
- **名伯楽との出会い**: 稀イベント。優秀なコーチ/部長を得て特定分野が継続ボーナス
- ※いずれも「狙って連打する」ものではなく、プレイの節目で訪れる。イベントはYAMLで追加可能（設計書04 §3）

### 1.2 信頼度と名声（二軸）
| 軸 | 対象 | 上げ方 | 効果 |
|---|---|---|---|
| 信頼度 | 校内（校長・保護者・部員） | 勝敗、怪我対応、学業配慮、選択肢イベント | 部予算、強化要求の通りやすさ、残留嘆願、**部員信頼→チーム士気の基礎値** |
| 名声 | 全国区 | 大会実績、甲子園、教え子のプロ入り | 新入生の質と数、練習試合の申込、取材 |

- **名声の時間応答（2026-08-26 案C+Dで改定・`CareerEngine.NextFame`）**:

  ```
  g = 4.0×公式戦勝数 + 30×甲子園出場 (+45 全国優勝) + 金星の加点（季上限8）
  g > 0 なら g ← g × (1 − 名声/100)                     … ①逓減（fame_gain_ceiling）
  保持 = min(名声,60)×0.80 + max(名声−60,0)×0.70        … ③維持の難しさ（fame_decay_high_threshold / fame_decay_high）
  名声' = 保持 + g
  名声' > 名声 + 12 なら 名声' = 名声 + 12              … ②年間上限（fame_season_rise_cap）
  名声' −= 取りこぼしの減点 × (1 + 名声/50)             … ④別枠（fame_upset_loss_fame_scale）
  名声' = clamp(名声', 0, 100)
  ```

  **2026-11-10（issue #868）「上げるより維持するのが難しい」**: 旧式は取りこぼしの減点（負のデルタ）を
  勝ちの加点と先に足してから逓減を掛けていたので、合計が正の年は罰まで「×(1−名声/100)」で縮んだ
  （名声80・4勝・格下に1敗: (16−3.5)×0.2＝+2.5。−3.5 が実質 −0.7）＝**名声が高いほど罰が軽かった**。
  - **④取りこぼしは別枠**: 上昇側（勝ち・甲子園・金星）にだけ逓減・年間上限を掛け、取りこぼしは**そのあとに別枠で**引く
    （`FameUpsetModel.SeasonSplit` が金星と取りこぼしを分けて返す）。さらに**名声が高いほど重く**
    `× (1 + 名声/50)`（名声0で×1.0・50で×2.0・100で×3.0）＝無名校の取りこぼしは今までどおり軽く、名門は許されない
  - **③60を超えた分は保持率0.70**（以下は従来の0.80）。名門ほど現状維持に勝ち続けなければならない
  - **採らなかったもの**: 「名門の早期敗退」の減点（試合の段階情報を名声式へ持ち込む配線が要る）と、
    「同ティアでも強さ差がしきい値以上なら取りこぼし」（`MatchDelta` の格下判定の細分化）。
    ①〜④の実測（下）で目標の目安に届いたので見送った
  - **実測**（強さ固定40年・47県の全国＋夏の県予選→甲子園の `SimulateSeason`・30シード・実ゲームの勝数は sim の約2倍なので ×2 でも測った）:
    定常名声（強さ55/65/75/85）は旧 33.6/45.6/61.8/74.4 → 新 31.8/40.2/52.4/61.7（×2勝）。無名校（強さ35〜45）はほぼ不変、
    常勝校ほど下がる。定常に達した年に格下へ1敗すると、その年の名声は**取りこぼし無しより 強さ55で5.7／75で7.3／85で7.8 低い**
    （旧は一律 3.5 を逓減後に引かれ、実質 0.7〜1 だった）。名声の増減は強さ75の常勝校で +2.1（旧）→ −2.1（新）に反転する
  - **残る性質**: 勝てなくなった王朝の崩れ方（100→年1勝を6年で 40 前後）は今までとほぼ同じ（60超の分が速く減るだけ）。
    名声は新入生の質・施設基金の寄付・転任オファーに効くので、常勝校の定常名声が下がる分、長期の難易度は上がる

  2026-08-15 案2（減衰0.80／勝4.0／甲30・時定数5年）で「速さ」を入れたが、**線形和のままだと
  名声のレンジを強さ60台の学校が使い切っていた**。原因は「公式戦勝数」の中身が
  **sim（`CareerEngine.SimulateSeason`＝夏の県大会＋甲子園だけ）と実ゲーム
  （`SchoolRecord.OfficialWins` の年差分＝秋の県大会・地区大会・センバツも数える）で約2倍ずれている**こと
  （実測: 強さ55で 1.60勝 vs 2.92勝／強さ65で 2.18 vs 4.93／強さ75で 4.82 vs 9.93。
  計測ハーネス `out/fame-wins-probe`）。定常＝勝数×20 なので強さ65で99（S）に張り付き、
  県大会を制した年は名声がいくつでも1年でSへ飛んでいた（13.4勝×4.0＋30＋8＝**+91.7**）。
  等級は10点刻み（`Tiers.FromStrength`）なので、プレイヤーには「F→D→急にA」としか見えない
  （2026-08-26 監督報告）。

  **勝数の数え方は変えず、上げ方の形で寝かせる**（`OfficialWins` 経路を触らないので実装が局所で済む）:
  - **①逓減**は上昇側にだけ掛ける。定常値が `100g/(20+g)` になり100へ張り付かない
    （年5勝＝50前後／年10勝＝67前後／年15勝でも90未満）＝**A・S は甲子園を積み重ねた監督のために空けておく**
  - **②年間上限**は**正味の**上昇量を頭打ちにする。帯幅10に対して+12＝1年で動くのは1段強まで
  - どちらも**下降側には効かない**＝王朝も勝てなくなれば一世代で崩れる（100→年1勝を6年で40前後）。
    名声は §2.1 の新入生の質へ直結するので、この減衰が「勝つ→良い新入生→また勝つ」の
    正フィードバックの**ブレーキ**を担う（`FameDynamicsTests`）
  - 育成の典型カーブ（強さ45→55→65→75→75・最後の年に県制覇＋甲子園）での軌跡:
    **7(G) → 16(G) → 28(G) → 40(E) → 52(D)**（改定前は 7 → 17 → 33(F) → 67(C) → 100(S)）
  - **未了**: 上と同じ `wins` を読む**信頼度**（`trust_per_win 4.0`＋甲子園20・減衰なし）と
    **指導力**（`coaching_growth_per_win 0.8`）も同じ倍率でずれている（年10勝なら信頼度 +40/年＝2年で100に張り付く）。
    名声とは別に扱う（`out/issues-pending/fame-rises-too-fast.md`）
- **番狂わせ加減点は実ゲームにも配線済み（2026-08-15・issue #170）**: 大会ブラケット確定時
  （`GameSession.FoldTournamentRecords`）に自校の各試合の `FameUpsetModel.MatchDelta` を**その時点の自校の強さ**で
  積み（`ManagerService.RecordTournamentUpsets`）、年度末の監督成長で畳み込む（上昇側は季8上限・下降側は頭打ちなし）。
  試合時点で固定するのは、実ゲームの自校の強さがロスター由来で季節ごとに動くため（夏は3年生込み・3月は新チーム）。
  年度をまたぐぶんはセーブ v12 の `managerPendingUpsetDeltas` で持ち越す。
  F校が格上のD校を1回倒すと +3×2段＝+6（旧来は勝利一律の+1.5だけ）＝序盤の「勝ったのに何も変わらない」を消す
- **信頼度の試合への効き方（間接・薄く）**: 信頼度は試合中のプレーに直接は作用しない。
  ただし部員からの信頼が厚いほど**チーム士気の基礎値が上がり**、士気が試合の粘り（接戦・終盤の
  踏ん張り）に薄く寄与する。信頼度→士気→試合、の一段挟んだ経路。
  精神力（§設計書02 §3）・主将（設計書09 §8）・伝令（§9.3）とは二重計上しないよう、
  信頼度は「土台の底上げ」に留め、場面ごとの補正はそれぞれの担当が持つ

### 1.3 転任システム（元祖忠実: 強制転任あり）
- キャリア初期は「教員監督」。**毎年3月に転任判定**があり、拒否できない
- 実績（例: 甲子園出場 or 名声閾値到達）で**「フリー監督」資格**を獲得 → 以降は残留自由・他校オファーの選択制（元祖踏襲）
- 信頼度が非常に高い場合、転任判定を「残留嘆願」で回避できることがある（救済、確率制）
- 転任時: 監督能力と名声は持ち越し、信頼度はリセット。育てたチームとの別れがドラマになる
- **部員は学校に所属する**（issue #641・2026-10-10 改定。旧決定「転任先は1年生10人で再スタート」は廃止）
  - 旧校は **AI校として全国に残る**。新設校（全国生成 seed=2026 に無い学校）なら新しい校IDで全国へ追加し、
    率いていた生成校ならその校IDのまま全国へ戻す。旧部員はそのAI校の永続ロスターへ移り、自校の安定IDを
    そのまま選手IDにする＝大会表や対戦で教え子と再会できる
  - 転任先AI校の部員を**自校が引き継ぐ**。転任先は全国から外れ、自校（専用ID −1）として大会に出る＝二重出場しない。
    自校＝専用ID の前提（Shell 約60箇所）はそのまま残し、全国一覧の側に差分（`NationOverlay`＝追加校＋外す1校）を
    重ねて実現する。差分はセーブ v21 に載る
  - AI校の選手は「いまの能力・適性・怪物種別・学年」しか持たないので、自校へ写すときに足りない隠し情報は
    **決定論で推定**する（2026-10-10 ユーザー決定）: 才能上限＝現在値＋新入生と同じ伸びしろ分布×残り学年の割合、
    成長タイプ・性格・練習効率・分野別伸び・怪我耐性は新入生と同じ分布から (校ID, 選手ID) 由来の専用ストリームで引く
    （`TransferRosterConversion`）。逆向き（自校→AI校）は隠し情報を捨て、背番号はAI校側が毎回振る
  - 成績: 自校の成績ストアは転任先の部員について**空から**積む（転任先AI校時代の成績は全国成績に (校ID, 選手ID) で残る）。
    教え子の転任後の成績は旧校AI校の全国成績に同じ選手IDで積まれる
- **フリー監督の候補校の数は名声で増える**（issue #869）: 数 = clamp(2, 10, 2 + floor((名声 − 50) / 4))。
  名声50以下は2校、70で7校、82以上で10校（`career.free_agent_offer_*`＝下限2・上限10・基準50・刻み4）。
  `BecameFreeAgent`（フリー化資格を得た年）と `FreeAgentOffer`（以降のオファー）の両方で同じ式。
  刻みはキャリアシム（80シード×30年・フリー期963年分）の名声分布に合わせた: フリー期の名声は中央値61・95%点86・最大88
  （逓減で100には張り付かない）なので、刻み5だと上限10（名声90）には誰も届かない。刻み4で、フリー期の約10%が10校、
  キャリア全体の約6割が一度は10校に届く。乱数は従来の独立ストリームのまま＝低名声の2校は改定前と同じ学校。
  候補が多いので、赴任先を選ぶモーダルは「候補10校＋残留」の11行がスクロールなしで見える大きさにする（tokens.uss の `--xt-*` 寸法）
- ゲーム的意味: フリー化までが「修行編」。弱小校を渡り歩いて指導力を磨き、フリー化後に本拠地を定めて王朝を築く、というキャリア曲線を作る

### 1.4 資金
- 収入: 学校予算（**年度の総括＝3月の入部予定者確定週**・信頼度連動）／大会報奨（勝ち進むほど）／OB・後援会寄付（名声、プロ入りOB数）
- 支出: 備品・施設（設計書03 §4）／合宿／スカウト年契約／遠征費
- 表記: 万円

**財布は2つ**（`Manager.Funds` / `Manager.FacilityFund`）。年100万台の部費で数千万の建物を建てる無理を構造で分ける。

| | 部費 `Funds` | 施設基金 `FacilityFund` |
|---|---|---|
| 収入 | 学校予算 80 ＋ 信頼度×0.8（年） | 学校の設備投資 100 ＋ 名声×20 ＋ 甲子園1000 ＋ 全国優勝5000（年） |
| 用途 | 練習道具・備品・合宿・年契約・練習試合 | 施設（照明／室内練習場／寮／トレーニング場／医務室）だけ |
| 初期 | **60万** | **0** |

初期値は**新設校スタート水準**（issue #585 確定事項5）。施設基金0は「初年度は建物が一切買えない」を
意味する（最安の医務室Lv1でも150万）。あわせて監督メタも新任水準で始める＝**名声0・信頼度30**
（信頼は中立50より下＝学校からも選手からもまだ信用されていない）。旧値（部費120万・基金100万・
名声10・信頼50）は「赴任してきた監督」の想定で、新設校を作って始める今の入口とは合わない。

現実の高校でも寮・室内練習場・ナイターは部費でなく学校法人の設備投資と後援会の寄付で建つ。
どちらの財布から出るかは `FacilityPurchase.WalletOf` にしか置かない。

### 1.4a 年契約（毎年かかる継続契約）

施設・練習道具・備品が**買い切り**で効果が累積するのに対し、年契約は**毎年払い続ける**契約で、
**いまどの段で契約しているかだけが効く**（Lv2 の年額と効果が Lv1 を置き換える＝累積しない）。
段を0へ戻せばその場で解約でき、年額も効果も消える。前払いは無く、年度頭にまとめて部費から引かれる。

| 契約 | 段 | 年額 | 単独維持に必要な信頼度 | 効果 |
|---|---|---|---|---|
| スカウト網 | 未契約 | 0 | — | **新規ゲームの既定**。新入生は毎年来るが、入部するまで誰なのか分からない。**スカウト候補は0人**（§2.4） |
| | Lv1 | 30万 | 常に可 | 県内を回る。質は素のまま＝<b>買うのは「見立て」だけ</b>（事前開示 ほとんど？）。**スカウト枠2人**（候補は寸評だけ） |
| | Lv2 | 80万 | **56** | 新入生の才能中心値 +3（近隣県まで）＋事前開示 一部見える。**スカウト枠3人**（候補に打・守・走・投の4分野ランク） |
| | Lv3 | 140万 | **131＝恒常維持不能** | 同 +6（全国に網を張る）＋事前開示 かなり見える。**スカウト枠4人**（候補に個別能力のランク） |
| 遠征 | Lv1 | 20万 | 常に可 | 県外の学校とも練習試合が組める |
| 打撃コーチ | Lv1 | 50万 | 19 | 打撃系の指導力 +10 |
| 投手コーチ | Lv1 | 50万 | 19 | 投手系の指導力 +10 |
| 守備走塁コーチ | Lv1 | 50万 | 19 | 守備・走塁系の指導力 +10 |

- **新規ゲームは全部未契約から始まる**（監督決定 2026-08-11）。以前は「年契約を導入しても収支が変わらない」ことを
  優先してスカウト網 Lv1 を既定にしていたが、監督が一度も選んでいない年額を既定で引き続けるのは筋が悪い。
  スカウトは「払っている間だけ効く」ものにする。**受動枠の新入生（毎年8〜13人）は契約の有無に関係なく来る**
  ＝未契約で困るのは「誰が来るのか分からない」ことと、質が素のままであること
  （旧セーブ v1/v2 の読み替えだけは当時と同じ内容の Lv1 ＝`ContractSet.LegacyScoutingLevel1`。
  `CareerCoefficients.ScoutCost` は年契約を持たない経路の固定費で、**スカウト網 Lv1 と同額に保つ**
  ＝片方だけ動かすと sim と実ゲームで支出がずれる）
- 専門コーチは**監督自身の指導力を書き換えない**（実効値だけ底上げする）＝解約すればその年から元に戻る。
  監督の上限99でクランプもしない（上限に張り付いた監督でもコーチを雇う意味を残す＝長期プレイのエンドゲーム対策）
- **遠征先は「各県の最強校」ではなく「全国の県外校を強さ順に等間隔で24校」**。最強校だけを並べると
  総合66〜95に固まり、赴任直後（総合33前後）では受諾率2%＝一生組めない相手しか出ない（実測）。
  等間隔なら全国最強から同格まで散り、名声が上がるほど上に手が届く段階ができる
- **年額は「その契約だけで部費が赤字にならない最低信頼度」で決める**（値上げ 2026-08-11・監督決定）。
  部費の差引は **`35 + 0.8×信頼度 − 年額`**（収入 `80 + 0.8×信頼度`、合宿45万）なので、
  必要信頼度 ＝ **`(年額 − 35) / 0.8`**。信頼度の上限は100＝**部費の上限160万／自由に使える上限115万**。
  改定前（15/30/50・コーチ30）は Lv3 でも必要信頼度18.8＝**新任監督（信頼30）が初年度から全部契約でき**、
  設計が謳う「どれを取るか」が成立していなかった
- **スカウト網 Lv3（140万）は恒常維持できない**（必要信頼度131＞上限100）。貯めた部費を切り崩して
  「勝負の数年だけ全国網を張る」契約になる＝これは意図した尖り方で、年契約の他の系統とは性格が違う
- 専門コーチは **1人なら常に、2人で信頼81、3人は不可**（150万＝必要信頼度143）。
  コーチ50万は「指導力+10 ＝ 監督自身の数年ぶんの成長に相当する」ことに見合わせた値
- 全部を最上段にすると 140+20+50×3＝**310万/年**で、自由に使える上限（115万）の約3倍。
  抱えすぎは経営画面の「部費 年間差引」が赤くなることで分かる
- **スカウト網の段は「候補の枠数」と「候補の見立ての段」を兼ねる**（issue #867・§2.4）。旧・能動勧誘枠
  （寮Lv1で年2名）はここへ一本化した＝**寮はスカウト候補の枠を持たない**。寮は「スカウト候補の距離の
  減点を打ち消す」効果として残る（§2.4 の `dorm_distance_relief`）

## 2. スカウト・新入生生成（ハイブリッド）

### 2.1 受動枠（毎年のメイン供給）
- 3月に入部予定者が確定、4月仮入部（能力は「？」、観察と育成眼で徐々に判明）
- 人数: 基準10人前後（実装は 8〜13人の抽選＝`intake_mean 10 / sd 1.5 / min 8 / max 13`）。
  **人数は名声で増やさない**（監督決定 2026-08-11）。名声・スカウト網が動かすのは**質だけ**で、
  強豪になっても入部者が増えるわけではない（設計初稿の「± 名声・前年実績・地域補正」は人数には適用しない）
- **才能生成モデル（重要・金太郎飴回避）**: 名声が決めるのは各能力値ではなく**選手1人の総合力（配る才能の総量）**。
  1. 名声から選手の総合力の期待値を決める（名声Cの学校ならC相当の総ポイント）。ここにばらつきを持たせる。
     **写像（2026-08-15 案D・オーナー決定「名声が高ければ新入生にB/Aが入ってよい」）**:
     `talentCenter = 32 + 50×(1−e^(−名声/50))`（`roster.fame_talent_center_span / tau`）
     ＝名声20→48(E)／40→59(D)／60→67(C)／80→72(B)／100→75(B。SD8 なので上位個体はA)。
     旧値（span 8・tau 30＝名声100でも40）は「自校の新入生が AI C校（強度60）の新入生にも届かず、
     自校がD以上へ行く経路が実質閉じている」ことが実測で分かり撤回（`out/growth-plan-2026-08-15.md`）。
     頭打ち（span）は残す。暴走の抑えは §1.2 の名声減衰が担う。
     **身体系（走力・地肩・スタミナ）の中心も 0.75 の傾きで連動する**（`roster.physical_talent_slope`。
     設計書01 §1.1b-2 の但し書き）。連動させないと B/A の新入生が「打撃Aで走力E」になり、機動力・肩・球速の
     天井でチームが C で頭打ちになる（AI校は `StrengthTeamFactory` で身体系が強度連動＝自校だけ天井が低い非対称だった）
  2. 総ポイントを各能力へ**ランダムな重み付けで凸凹に配分**する（均等割りにしない）。
     → 総合Cでも「ミートB・走力D・肩A・守備E」のように内訳に個性が出る
  3. 配分の偏りの強さ自体もばらつかせる → たまたま平均的に配れた「オールC型」も自然に混じる
- 才能上限・伸びしろ（設計書01）も同様に分野別で凸凹に配る → 現在値だけでなく伸び方にも個性
- まれに分布の外れ値として「怪物」（突出した総合力／一芸特化）が出現。名声で出現率がわずかに上がる
- スカウト年契約（元祖踏襲）: なし / 地元 / 広域 の3ランク。契約金は年払い
  - 効果1: 新入生の**総合力の期待値**が上振れ（内訳の凸凹は維持）
  - 効果2: 入部予定者の隠しパラメータの事前開示精度が上がる

### 2.2 能動勧誘枠（寮で解禁、少数）── issue #867 で §2.4「スカウト」へ統合・廃止

旧実装（issue #588）は寮Lv1で年2名の勧誘枠を解禁していたが、**監督が狙って探す**遊び
（欲しい分野を選ぶ・段で見える情報が増える・進路希望）を一本化するため、年契約「スカウト網」の段
が持つ枠（§2.4）へ置き換えた。寮は「候補の距離の減点を打ち消す」効果だけを残して存続する
（§1.4a・§2.4 の `dorm_distance_relief`）。中学生リスト・成功率モデルの考え方自体は §2.4 が継承している。

### 2.3 詰み防止
- ポジション配分は原則ランダムだが、捕手のみ最低保証（部に捕手適性が枯渇しない下限補正）
- 補正の強度はバランス検証で調整（硬派さを損なわない最小限に留める）

**実装（#587）: 3月確定 → 4月仮入部**

- **確定週は3月1週目**（`SeasonCalendar.ProspectConfirmWeek` = 第46週）。生成そのものは年度替わりで
  呼んでいた `ProspectGenerator.Intake` と**同じ入力・同じ乱数消費**で、`RosterLifecycle.ConfirmIncoming`
  へ切り出して**確定を前へ倒しただけ**（`ProspectSplitTests` が「2段に分けた結果＝従来の1段生成」を1ビットで固定）。
  人数の抽選規則（`intake_mean/min/max`）も才能の配り方も変えていない
- **`existingNames` の落とし穴**: 年度替わりの③は「卒業を済ませた後のロスター」の氏名列を渡している。
  3月時点ではまだ卒業していないので、そのまま渡すと下の名前の重複回避がずれる。
  **卒業後に残るのは現1・2年だけ**なので `Grade <= 2` で絞れば順序まで含めて同一列になる
- **年度の総括も3月へ前倒しした**（監督決定 2026-08-11）。総括（名声・信頼度・指導力・部費収入・年契約の年額）を
  4月のままにすると、3月時点の名声は**まだ今年度の夏・秋を織り込んでいない**ので
  「甲子園に行った年の実績が新入生に効くのが1年遅れる」。総括はその年度の大会が全部終わった後（3月）に回し、
  4月側の呼び出しは二重適用ガードで no-op になる（3月を跨がずに年度替わりへ来た進行の取りこぼし防止として残す）
- **効果2（事前開示精度）**: スカウト網の段が `ContractTier.ProspectDisclosure`（0〜1）を持ち、
  未契約=0「なし」／Lv1=0.15「ほとんど？」／Lv2=0.45「一部見える」／Lv3=0.75「かなり見える」。開示は
  ①推定カテゴリ強さに乗る誤差σ（`scouting.estimate_sd_max/min`＝20→4）②隠しパラメータ1項目が判明する確率
  （`scouting.reveal_min/max`＝0.05→0.85）の2つへ写す（`ProspectScouting`）。実測（Lv1→Lv3）で
  「？」の平均は 3.3個 → 1.2個 まで減る
- **見立ての抽選は生成とは別ストリーム**（不変条件#2）。スカウト網の段を変えても**来る選手は1ビットも動かず**、
  変わるのは「どこまで見えるか」だけ（受け入れスクショの `sameProspects=True` で確認）
- **未契約（開示0）は見立てそのものを出さない**。開示0の推定は誤差σ20でほぼ雑音なので、
  色付きランクとして出すと画面が嘘をつく＝一覧も詳細も「？」で通す
- **効果1（質）の効き幅の実測**（3,000コホート・約3万人、talentCenter 32→35→38）:
  平均能力 34.96 → 36.68 → 38.41／打撃力 32.07 → 34.27 → 36.49／投手力 29.30 → 30.48 → 31.68。
  効くのは平均より**当たりの頻度**で、最良軸がC以上の選手の割合が **2.78% → 3.99% → 5.74%**、
  B以上が **0.18% → 0.31% → 0.50%** と倍化する（1学年10人なら「C以上が3.6年に1人」→「1.7年に1人」）。
  走力の伸びが小さい（40.25→41.81）のは走力・肩・スタミナが**身体系＝名声独立**で配られるため
  （※2026-08-15 案D で身体系中心は 0.75 の傾きで連動するようになった。この実測は改定前の値）。
  名声換算では **Lv3（+6）≒ 旧写像の名声60〜100 相当**（旧: Fame30→+5.06／Fame100→+7.71・上限+8。
  新写像では名声8前後に相当＝スカウト網の相対的な重みは小さくなった）で、両者は加算される
- **名声とスカウト網が食い合うことはない**（実測で確認・2026-08-11）。talentCenter は
  `TalentCenterFromFame(fame) + ScoutTalentAdd` の**単純な和**で、頭打ち（`fame_talent_center_span`）が
  かかるのは**名声側だけ**。総合力の抽選 `clamp(Gaussian(center, 8), 10, 90)` の上限90が効き始めるのは
  center 80 付近（実測: center80で10.4%・88で40.0%が切り詰められる）。旧写像（span 8）では到達しうる
  center の最大が 32＋8＋6＝46 で34ポイントの余裕があった。**2026-08-15 案D（span 50）では名声100＋Lv3 で
  32＋50＋6＝88 に届き、上限90の切り詰めが効き始める**＝名声を極めた学校ではスカウト網の上積みが
  頭打ちに食われる（それでも「契約すると必ず良くなる」は保たれる。ここは体験で確認する）。
  むしろ**名声が高いほどスカウト網の見返りは大きい**（C以上率の増分は Fame0 で +2.84pt、
  Fame100 で +6.58pt。閾値をまたぐ裾の量が増えるため）
- ただし**伸びしろ余地（上限−現在値）はごくわずかに縮む**（26.72 → 26.34・実測 −1.4%）。
  能力上限が99でクランプされる分だけで、上限そのものは 58.5 → 66.2 と上がる＝完成形は必ず上
- **見立ては選手に触れない**（`ProspectScouting` は純関数で能力を書き換えない）＝スカウトが読み違えても
  入部する選手は変わらない。4月に入部したら実値が見え、`IncomingClass` は選手の実体を手放して
  見立てだけを残す（入部後の答え合わせに使う・セーブに二重に載せない）
- **旧セーブ（v4以前）**は予定者を持たないので、4月に進めると `AdvanceYear` の従来経路
  （`incoming=null`＝その場生成）へそのまま落ちる

**実装（#589）**: 投手供給の下限（#377 `EnsurePitcherSupply`）と同型で
`ProspectGenerator.EnsureCatcherSupply` を新入生コホートに掛ける。

- **境界**: 「捕手として読める」＝捕手適性 ≥ `roster.catcher_aptitude_floor`（既定 **50**）。
  判定は `CatcherRoleResolver` にしか置かない（閾値のコピーを各所に書かない）。
  50 は `fielding.aptitude_neutral`＝適性補正が付かない点（×1.0）で、これ未満は
  「捕手に置くと不利補正が付く＝不慣れ」。投手役が**比較**（投手適性 vs 最良守備適性）なのに対し、
  捕手は8守備枠の1つ＝誰かが必ず座る枠なので**絶対の下限**で読む
- **効かせ方**: 読める選手が0人のコホートでだけ、捕手適性が最も惜しい1人を境界ちょうどまで引き上げる。
  乱数を使わない決定論操作（不変条件#2）で、**能力（Catching / ThrowAccuracy 等）は底上げしない**
  ＝「その年は捕手が居ない」苦しさは絵に残る
- **候補から投手役を外す**: 捕手適性を上げると最良守備適性が上がり投手判定（`LeansPitcher`）を割るため、
  投手を持ち上げると直前の `EnsurePitcherSupply` が保証した投手供給を壊す
- **実測（下限50）**: 発動率は新入生コホート（8〜13人）の **0.122%**（40,000コホート）。
  参考に閾値を上げたときの発動率は 55→0.69% / 58→1.68% / 60→2.72%（投手版の実測は 2.12%）。
  下限50は「ほぼ発動しない保険」＝§2.3 の『最小限』に収まる
- **AI校には入れない**: AI校は1学年11人×3学年＝33人の永続ロスターから毎回選抜するため、
  ロスター全体で読める捕手が0人になる確率は 20,000校の実測で **0件**（ロスター最高捕手適性の最小値63）。
  `PersistentRosterCoefficients` に `CatcherCountFloor` は置かない
- 参考: 下限が効かない通常のコホートでも、実際に捕手へ就く選手の適性は中央66・p5=37・p1=25
  （`RosterTeamBuilder` は捕手単体でなく**守備8枠の実効守備力の総和**を最大化するので、
  コホート最良の捕手適性の持ち主が捕手に就くとは限らない＝設計どおり）
- **AI校の守備位置は肩も見る（issue #767・2026-11-03）**: `AiTeamBuilder.AssignFieldPositions` の割当重みは
  「実効守備力＋打撃総合×`field_slot_batting_weight`＋**肩Lv×位置別重み**（`field_slot_arm_weight_*`）」。
  重みは 捕手0.6／遊撃0.6／右翼0.5／三塁0.4／中堅0.3／二塁0.2／左翼0.1／一塁0。実測（seed 2026・600校・年度3）:
  先発の肩の中央値 遊撃47→53／右翼48→53／一塁47→44／左翼48→44（旧は全位置48前後で同じ）。守備・打撃の総和はほぼ不変
  （先発守備平均 49.59→49.56）。**並べ替えの上限はチーム内の肩の幅で決まる**（先発8人の肩の最大−最小が平均18）＝
  重みを上げても遊撃の肩は+10程度で頭打ちで、D校以下に肩75超の遊撃手はほぼ生まれない。自校は対象外（守備位置はプレイヤーが決める）
- **AI校の肩の個人差σ＝12（`roster.ai_arm_sd`・issue #767）**: 旧は全能力と同じσ6で、自校の新入生の身体系（`physical_sd` 12）の
  半分だった。σだけ12へ揃え中心（学校の強さ）は据え置き。送球精度は同じ標準正規値からσ6で作る（旧値と1ビット一致）。
  位置別重みと合わせた実測: 先発の肩の中央値 遊撃60／右翼57／捕手57／一塁37／左翼39、D校遊撃手の肩75以上 30%（σ6では4%）、
  C校 64%。`simulate-tiers` の得失点はσ6と±0.2点（誤差内）。エース球速は D校の中央値 137.4→137.8（肩から球速を推定する
  野手兼投手がエースになる校が出る）

### 2.4 スカウト（欲しい選手を探す・見立てる・口説く・issue #867）

**オーナー決定（2026-11-09）に基づく最終仕様。** 旧「年契約を払うと入部予定者が少し見える」（§2.1 効果2）
と旧「寮の能動勧誘」（§2.2・廃止）を、「監督が狙って探し、見立てて、口説く」遊びへ作り直した。

#### 受動枠との関係
入部の総数は今どおり**年8〜13人**（§2.1・名声で増やさない）。そのうち**スカウト枠の人数分だけ**を
スカウトが口説き落とした候補と差し替える。口説き損ねた分は通常どおり受動枠の自動の子が入る＝
**失敗しても人数は詰まらない**。受動枠の生成乱数は動かさない（候補・見立て・訪問・成否は別ストリーム
＝`ScoutingTests.Scouting_DoesNotDisturbPassiveIntake` が固定）。

#### 枠と段ごとの開示
枠の数と「見えるもの」は年契約「スカウト網」の段が兼ねる（§1.4a）。

| 段 | 枠 | 開示 |
|---|---|---|
| 未契約 | 0人 | スカウト自体が起きない |
| Lv1 | 2人 | 寸評だけ |
| Lv2 | 3人 | 寸評＋打・守・走・投の4分野ランク |
| Lv3 | 4人 | 寸評＋4分野ランク＋個別能力のランク |

候補リストは**枠の約3倍**（`scout.candidates_per_slot`=3）が届く。隠し素質（成長タイプ・伸びしろ・怪物）は
**どの段でも見せない**（入部後の育成眼・気づきの楽しみに残す）。段は候補リストを作った時点で凍結し、
後から契約を上げても「もう見ているリスト」の見え方は変わらない（受動枠の事前開示と同じ約束）。

#### 寸評
能力から決定論で文章を作る（文言の正典は `data/scout-blurbs.yaml`）。ノイズ入りの4軸（打/守/走/投）の
最大値から軸と水準（高/中/低）を選び、対応する語彙から1文を引く（`ScoutModel.PickBlurb` /
`ScoutBlurbPhrases`）。**段が低いほど見立てのノイズが大きい**（`scout.report_noise_sd_tier1/2/3`＝
18→10→4）ので、Lv1 では寸評が実態と食い違うことがある。段を上げるほど当たりやすくなる。

#### 探す分野
分野（投球／打撃／守備走塁／おまかせ）を選ぶと、生成する候補プールをその分野の強さ（ノイズ付き）で
選抜し、能力の傾きだけを変える（`ScoutModel.BuildCandidates` の `field` パラメータ）。候補に
「投手」「野手」のラベルは一切付けない（CLAUDE.md「守備位置・適性はゲームが提示しない」。
`PitcherRoleResolver.LeansPitcher` 等はスカウト側では一切参照しない）。

#### 年間の流れ
新チーム発足（夏の大会後）に探す分野を選ぶ（いつでも変更可・リスト生成時点の値で凍結） →
秋の大会後（第24週 `SeasonCalendar.RecruitListWeek`）に候補と寸評が届く → 冬に訪問で口説く →
3月（第46週 `SeasonCalendar.ProspectConfirmWeek`）に成否と入部が確定。既存の節目をそのまま使う
（新しい週は増やしていない）。

#### 入部の成否
進路希望は3種（候補1人に1つだけ割り当て）。**入部の見込み（%）は画面に出さない**
（オーナー決定・ワイヤー案A）。

- **名門志向**: 名声が高いほど来る（`scout.prob_per_fame`）
- **出場機会志向**: その子より強い部員が少ないほど来る（`ScoutModel.OpportunityScore`＝候補の最良4軸より
  弱い現ロスター部員の割合。`scout.prob_per_opportunity`）
- **地元志向**: 近いほど来る（`ScoutModel.Closeness`＝同県1.0〜遠方0.0。`scout.prob_per_local`）

距離の減点・競合校の格の減点・訪問の積み上げは進路希望に関わらず全員へ共通で効く（§2.2 の成功率モデルを
継承）。寮は距離の減点を6割打ち消す（`scout.dorm_distance_relief`）。競合校との争奪戦も残す
（訪問1回ごとに `scout.rival_event_prob`=0.22 で競合校の格が1段上がる）。

**進路希望の分布比・見立てノイズの具体値は issue 本文・オーナー決定に数値指定が無いため、無難な初期値
（等分・旧 §2.2 の値を踏襲）を置いた。バランス実測は未（issue #867 の『新入生の質の分布は専用の実測で』
を参照。統計帯はロスター生成を測らないため Heavy の安全網にならない）。**

#### 費用
スカウト網の年額（30/80/140万・§1.4a）はそのまま＋訪問費は距離依存（5〜30万・今どおり）。
探す分野の指定は無料。

#### 画面（ワイヤー案A・オーナー決定2026-11-09）
左に候補一覧（氏名・地方・段に応じた分野ランク・進路希望・訪問回数）、右に選択候補の詳細
（寸評・ランク・進路希望・競合校・訪問ボタン）。行ごとのボタンは置かない。入部の見込みは一切出さない。

### 3.2 フラグ管理
- グローバルフラグ（キャリア通算） / 年次リセットフラグ / 選手個別フラグ の3層
- 発生制御: 同一週最大1件、同一イベントにクールダウン、重み付き抽選

### 3.3 初期ラインナップ（抜粋20件）
- 固定: 入学式、仮入部→正式入部、テスト週×4、夏合宿、冬合宿、文化祭、ドラフト会議、
  プロ入りOBの挨拶訪問（元祖踏襲）、卒業式、転任辞令（3月・判定連動）
- ランダム: 怪我、雨天週、取材、プロスカウト視察、OB寄付、感染症で部活動停止
- 選択肢: エースの違和感、練習サボり、無名1年の自主練、保護者からの起用クレーム、
  部員間の不和、他校からの引き抜き噂（フリー化後）
