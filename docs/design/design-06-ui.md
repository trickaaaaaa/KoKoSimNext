# 設計書06: UI設計（現代的マネジメントUI）

方針決定: 元祖風のテキスト主体ではなく、**現代的なマネジメントゲーム風ダッシュボード**
（Football Manager系の情報設計を高校野球の題材に翻訳する）

---

## 1. 実装技術: Unity UI Toolkit を採用

- 管理画面系はすべて **UI Toolkit（UXML/USS）** で構築する
- 理由: レイアウトとスタイルがテキストファイル（UXML/USS）で完結するため、
  **Claude Codeがエディタを介さずUIを直接書き・修正できる**。表・リスト中心の画面との相性も良い
- uGUI/3D空間は将来の試合3Dビュー専用に温存
- 構造: 純C#エンジン → ViewModel層 → UXMLバインディング（エンジンにUI依存を持ち込まない）

## 2. 情報設計の原則

- **ハブ＆スポーク**: ホームダッシュボードを中心に全機能へ1クリック
- **通知フィード駆動**: 週送りで起きたこと（イベント・新聞・成長・怪我）はすべてフィードに流れる。
  「まとめて進行」が止まった理由が常に一目で分かる
- **等級の視覚言語統一**: S〜Gに固定カラー＋文字併記（色覚対応）。能力・球種・ティア全てで共通
- PC（Windows）前提: 16:9、マウス主体＋キーボードショートカット

## 3. 画面一覧

### 3.0 タイトル画面（起動直後の入口・issue #482）
Play すると最初に出る簡易タイトル。共通ナビ（TopBar）は出さない（どのシェルサービスもまだ
遅延初期化されていない状態のため）。背景は design-19「デーゲーム・フルNB」の色ブロック
（空/スタンド/芝/土の4段。B案＝球場バック型）をそのまま使い、写真・3Dは使わない。
項目は3つだけ:
- **はじめから** → **新規ゲーム設定（§3.0a）** へ。新設校を作ってからホームへ渡す
- **つづきから** → セーブスロット選択（§3.0b）。セーブが1件も無ければ非活性表示（`SaveSlots.AnySaveExists()`）
- **終了** → `Application.Quit()`（Editor では `EditorApplication.isPlaying = false`）

「タイトルへ戻る」導線は §3.0c（ホームメニュー）参照。

### 3.0a 新規ゲーム設定（新設校スタート・issue #585）
タイトルの「はじめから」から来る唯一の入口。**新設校を作って**ホームへ渡す。共通ナビ（TopBar）は
タイトルと同じ理由で出さない（シェルサービスが未初期化）。

レイアウトは**B案「上下2段」**（2026-08-11 監督選定）:
- **上段＝本拠地と校名**: 都道府県（47件）／県内地区（採用県のみ）／校名（自由入力＋その県の地名から候補6件）
  ／確認の1行（「神奈川県　湘南台高校　／　第1地区」）
- **下段＝ユニフォーム配色（左）と見え方（右）**: チーム設定画面（§3.7 相当）と同じ「左＝領域行／右＝プレビュー」。
  配色UIは部品辞書 `UniformColorPicker` を共有＝**同じ実装を2つ作らない**
- 主要操作は1つだけ（「この高校ではじめる」）。校名が空／長すぎ／県内の生成校と重複のときは押せない

決めた内容の反映:
- 校名・本拠県・県内地区は `NationService` のセッション状態になり、セーブ（v4）にも載る
- 初年度は**1年生10人だけ**（人数は抽選しない）。投手役・捕手は供給下限（#377/#589）が必ず立てる
- 監督の初期リソースは新設校水準（design-04 §1.4）

**県内地区について**: 選べるのは `data/pref-formats/` が `district_assignment: geographic` の県だけ
（現状は神奈川4・兵庫5）。表示は「第N地区」で統一する（YAML の `districts:` の名前は県によって
運用ブロック数と食い違うため使わない）。なお **Unity の大会は現状 `PrefFormat` を使っていない**ので、
地区は「将来 group_split が入ったときに効く器」であって今は勝敗に影響しない。

### 3.0b セーブスロット選択（issue #508・F1／#509・F2 で保存/戻るを追加）
タイトルの「つづきから」と、ホームメニューの「セーブ」（§3.0c）の2箇所から開く単一画面
（`ScreenRouter` の `ExtraScreens`＝`SaveSlots`。タブなし）。呼び出し元は遷移直前に
`SaveSlots.Entry`（`Title`/`Home`）を設定し、`SaveSlotsController` はこれでボタン構成を切り替える。
開いた時点ではまだセーブを読んでおらず、どのシェルサービスも遅延初期化されていないため §3.0 と同じ理由で
共通トップバーは出さない（ホーム経由でも同様。代わりに `ss-back` で戻る）。

- **レイアウト＝案2（リスト＋詳細ペイン）**: 左に手動3枠を32px行で並べ（`.card--list`）、
  右に選択枠の詳細（学校名・年度・週・保存日時）と操作ボタン（`.card--detail`、幅は共通トークン
  `--w-editor`）。`HomeDashboard.uxml` の新チーム発足モーダル（`nt-list`/`nt-detail`）と
  `PracticeMatch` の `.card--list`/`.card--detail` に共通する行選択の見た目（32px行・hover・選択時の
  左アクセント）をそのまま踏襲する。オーナー承認（issue #508 コメント・2026-08-07）
- **スロットID**: `manual1` / `manual2` / `manual3`（`SaveSlots.AllSlotIds`）。ファイル名は
  `SaveGameIO.PathForSlot(slotId)` がそのまま使う。**オート枠は廃止**（監督決定 2026-08-09。下の「保存は
  手動だけ」参照）。旧 `auto.sav` は一覧・活性判定に入るたび `SaveSlots.PurgeLegacyAutoSave()` が消す
- **出すボタンはタイトル経由＝「読込」「削除」だけ**（オーナー判断のA案）。「今保存すべき進行中の
  ゲーム状態」が無いため保存は出さない。**ホーム経由（issue #509）は「保存」も出す**（大会中は
  `SaveGameIO.CanSave` で非活性＋理由1行）。ホーム経由だけ空き枠も選択できる＝新規に保存する先として選ぶため
- **削除は確認ダイアログを挟む**。確認ボタンは警告色 `--color-warn`（部品辞書 `components.uss` の
  `.dlg-btn--warn` を新設）。破壊的操作にだけ使う（UI原則②）
- **空きスロット**は「── 空き ──」表示で、行のクリックハンドラを配線しない（押しても何も起きない）
- **壊れたセーブ・未対応の版**は例外を投げず一覧に出す（`SaveSlots.ReadInfo` が `Corrupt` フラグを立てる）。
  詳細ペインに「読み込めません」と出し、読込ボタンは非活性、削除ボタンは活性のまま（壊れた枠を空けられる）
- 学校名は `SaveState` に無い値（`NationService.ManagerSchoolName`、現状は全セーブ共通の定数）ので
  Shell層で組む。保存日時はファイルの更新日時（`File.GetLastWriteTime`）、版はヘッダのみ軽量に読む
  `SaveCodec.PeekHeader`（ロスター等は読まない・完全復元より軽い）

### 3.0c ホームメニュー（issue #509・F2）
ゲーム中のセーブ導線・「タイトルへ戻る」は**ホーム画面のこのメニュー1箇所だけ**に置く
（オーナー判断・issue #509コメント2026-08-07。試合中のポーズメニューには置かない＝
ホームに居る間だけが対象なので「観戦中は保存しない」（issue #565 F1）は自然に満たされる）。

- **入口**: ヒーロー帯（直近の予定）右端の「≡ メニュー」ボタン1つ（`hm-menu-btn`）。
  `hm-hero__match`/`hm-hero__plain` が `flex-grow:1` なので追加のレイアウト調整なしに右端へ収まる
- **メニュー内**（`tm-scrim`/`tm-card` の同一document内オーバーレイ。大会モードのダイアログ群と同じ部品）:
  - **セーブ** → セーブスロット選択（§3.0b）をホームモードで開く。保存できない局面では
    `SaveGameIO.CanSave` を見て非活性＋理由1行。**理由文は `SaveGameIO.SaveDisabledReason()` の一箇所**に置く
    （UI側で条件を書き写すと、条件が増えたときに片方だけ直して表示と実挙動が食い違う）
  - **タイトルへ戻る** → 確認ダイアログ（破壊的操作＝警告色 `tm-btn--warn`）を挟み、確定で
    `SaveGameIO.ResetForNewGame()` ＋ `HomeState.Reset()`（通知フィードは保存対象外の一時状態だが、
    次の新規ゲームへ前セッションの出来事を混ぜないためここで一緒に捨てる）→ タイトル画面。
    背景の全国裏試合／残りブラケット消化（`NationBackgroundSim`/`BracketFinishSim`）を `EnsureCompleted()`
    で先に完了させてから静的リセットする（`GameClock.Advance` の年度替わりと同じ作法。issue #529 参照。
    完了前にリセットすると、直後に新セッションが背景シムを再始動した場合に旧ワーカーが共有カウンタを
    奪い合う実害がある）
  - **閉じる** → メニューだけ閉じる
- **大会中も入口はこのメニュー1箇所のまま**（監督決定 2026-08-09）。大会モードでも画面はホーム
  ダッシュボードのまま（「今週を進める」が「1日進める」に変わるだけ）で ≡メニューは常に出ている＝
  日送り中はここから保存できる。**試合の観戦中（MatchLive）には入口を置かない**＝中断ポップアップは
  伝令／交代／スキップ／再開の4つのまま（UI原則⑦）。大会中の `CanSave` は issue #565 F1 で true になった

#### 3.0d 「システム」タブ（共通ナビ・issue #565 A案・オーナー承認 2026-08-10）

共通ナビ（`Components/TopBar.uxml`）の**末尾**に「システム」タブを置き、押すとセーブスロット画面
（§3.0b）を開く。**≡メニューは残す**（入口が2つになるが、どちらも同じ1画面へ着く）。

- **新規画面は作らない**。同じ `SaveSlots` 画面を3つの入口で開き、`SaveSlots.Entry` で見た目を変える
  （`SaveSlotsEntry`: `Title` / `Home` / `Tab`）

  | 入口 | トップバー（タブ帯） | 「◀ ホームへ戻る」 | 保存 |
  |---|---|---|---|
  | タイトルの「つづきから」 | 出さない | 出さない | 出さない |
  | ホームの ≡メニュー | 出さない | **出す** | 出す |
  | **システムタブ** | **出す** | 出さない | 出す |

- **タイトル経由でトップバーを出せない**理由は据え置き＝この画面はシェルサービスの遅延初期化より前に
  開くので、部費・総合ランクを引いた時点でロスターや全国が生成されてしまう
- タブ経由で「戻る」を出さないのは、**移動はタブで行う**から（戻り先が曖昧な戻るボタンを置かない）
- タブ経由では「今週を進める」も他のタブと同じ `WeekAdvance.FromSideScreen` へ配線する
  （配線しないと死にボタンになる＝issue #134 で潰した穴を再発させない）。`ScreenRouter.WeekAdvancers`
  にも加える＝ここで大会開幕週に入っても開幕演出のためホームへ回送される
- 入口の切り替えは `ScreenRouter` のナビクリックが `Entry = Tab` を立てて行う。**同じ画面を
  `SetActive(true)` しても `OnEnable` は再発火しない**ので、入口を変えて開き直すときは
  必ず別画面を挟むこと（撮影ハーネスで踏んだ）

#### 保存は手動だけ（オートセーブ廃止・監督決定 2026-08-09）

保存は**プレイヤーが手動3枠へ行う明示操作だけ**にする。`GameClock.Advance` の週送りは
ファイルIOを一切起こさない（issue #509 で入れたオートセーブを撤回）。

- 撤回の理由: オートは「大会に入った週だけ `CanSave` が false で黙って書かれない」穴があり、
  当てにすると**大会前まで巻き戻る**事故になる。自動と手動が混ざると「どこまで保存されているか」が
  プレイヤーから見えないのが根本問題で、明示操作だけにすれば見えるようになる
- **未保存の可視化**: 「タイトルへ戻る」の確認ダイアログに、最後の保存からの経過を1行出す
  （`hm-menu-title-since` / `.tm-dialog__sub`。例「最後の保存: 2028年5月5週目（12週前）」、
  未保存なら「この進行はまだ一度も保存していません。」）。基準は `SaveGameIO.LastSavedAt`
  （保存・読込の成功時に更新、`ResetForNewGame` で null。**セーブ対象ではない**セッション内の目安）。
  警告色は使わない＝本当の警告に取っておく（UI原則②）
- 絶対週の式（`(年度-1)×週/年＋週`）は `GameClock.AbsoluteWeekOf` の一箇所だけに置く
  （`ManagerService.AbsoluteWeek` もここを通す）

#### セーブの実測値と往復の担保（issue #483 の締め・2026-08-09）

- **サイズ（#483 論点2の結論）**: 全4008校を materialize した最悪ケースで **JSON 96.3 MiB → gzip 9.95 MiB**
  （1校あたり約2.6 KB・圧縮率10.3%）。実プレイに近い「本拠県211校だけ materialize」では **559 KiB**。
  差分保存・バイナリ化は当面**不要**と判断する。回帰は `SaveSizeTests`（Heavy・上限50 MiB）が張り、
  実測レポートは `out/overnight/save-size-measurement.txt` に出る
- **大会中も「試合と試合の間」なら保存する（#483 論点3を撤回・issue #565 F1・2026-08-10）**:
  手動セーブ一本にした結果、大会中は保存手段が一切無くなり、県211校＝最大8試合ぶっ続けで中断できなく
  なったため。`TournamentRunner` の可変状態（ブラケット・乱数の内部状態・球数台帳・試合ログ）を
  `SaveState.Tournament` へ載せ、復元は `TournamentEntry.RestoreRunner` が resolver ごと組み直す。
  スキーマ版は 1→2（v1＝大会状態なしとして読む）。
  - **保存しない局面**（`SaveGameIO.CanSave` が false）: 観戦中（`MatchProgression` を持つ＝F2 の対象）／
    結果モーダルの表示待ち／大会終了の後始末待ち／残りブラケットの集計中／試合開始フローの途中。
    いずれも「まだ確定していない副作用」を抱えた状態で、保存すると復元後に週送り・通知・戦績の
    畳み込みが失われて進行が詰まる
  - **シード配置は保存された並びを使う**（組み直さない）。シードは Strength 順で決まるが自校の Strength は
    大会中の実戦成長で動くため、復元時に組み直すと**樹形図の並びが変わる**（絵にも数字にも出ない形でずれる）
  - **全国裏試合（`NationBackgroundSim`）は保存前に `EnsureCompleted()` で待つ**。待たずに保存すると
    他46県の途中結果を焼いたセーブができ、ロード後に再開する手立てが無い（進捗を保存していない）ので
    その県の成績が永久に欠ける。待ち時間が出るのはこのためで、単なる作法ではない
  - **裏カードの全国成績への畳み込みは「計算時」ではなく「ランナーが記録した時」**（`onBackgroundMatch`）。
    プレフェッチは同じ resolver で先に計算するので、計算時に畳むと「まだ記録していないカード」が成績へ入る。
    セッション内はメモ化が1カード1回を守るので露見しないが、**セーブを挟むとメモが消えて二重計上**になる
    （実測 2026-08-10: ロード後の DTO が保存時より大きくなった）
- **往復の担保は2段**。engine の `SaveCodecTests`/`SaveDeterminismTests` は DTO の形と決定論を見るが、
  **Shell の static サービス群（Capture/Restore の配線）と Unity のファイル IO は通らない**。
  static が本当に死ぬのは Play 停止（ドメインリロード）の瞬間だけなので、同一 Play 内で往復させても
  「消えていないだけ」を一致と誤認する。ドメインリロードをまたぐ確認は
  `Assets/Editor/SaveRoundTripProbe.cs`（PhaseA→Play停止→再Play→PhaseB）で行う

### 3.2b 成績（眺めてニヤニヤする中核画面）
1球単位エンジンの副産物として詳細成績が自動集計される。**3つの時間軸**で切り替えて見られる:
- **今大会成績**: 進行中の大会での暴れっぷり（リアルタイムに伸びる）
- **公式戦通算**: 高校3年間の対外試合の積み上げ（そのチームでの物語）
- **キャリア通算**: 卒業後も継続。教え子がプロ入り後も追える（設計書04 教え子名鑑と接続）

指標（物理エンジンがあるので現代的に）。**どちらを出すかは役割ではなく出場実績で決める**
（登板があれば投手成績、打席があれば打撃成績、二刀流は両方。設計書01 §1.1a・issue #379）:
- **打撃**: 打率・本塁打・打点・盗塁の基本＋出塁率・長打率・OPS、
  打球データ由来の平均打球初速/角度・最長本塁打距離
- **投球**: 防御率・**投球回**・奪三振＋K/9・WHIP・被打率、平均球速・最速の推移
  （高校野球なので勝敗は用いない。投球回で連投・酷使を可視化）
- 幅の狭い場所（スタメン設定の比較カード等）では全指標を並べず**代表指標に絞る**。
  詰めて収めようとすると値がラベルに重なる（issue #388）＝減らすか横に展開する
- 年度別/対戦相手別の内訳、月間MVP級のハイライト、キャリアハイの自動ピックアップ
- **記録室（設計書 3.9）連携**: 校歴代記録・全国記録に絡むと通知フィードで祝う

### 3.3b 背番号・ベンチ入り登録
- 部員リストから**ベンチ入り20名を選び、背番号1〜20を割り当てる**ドラッグ操作が主体
- 選ばれなかった部員は「ベンチ外」ゾーンに残り一目で分かる（部員20名超の学校ではここが実質的なメンバー選考）
- 慣例番号の自動割り当て補助: 1=エース / 2=正捕手 / 3〜9=各守備位置 / 10〜=控え（強制ではなく提案）
- **大会ごとに登録し直せる**（夏用・秋用でメンバーが変わる。設計書03の年間カレンダーと連動）
- 番号1を誰に託すか等はドラマ要素。信頼度・士気に軽く波及させてもよい（要調整）
- 自動編成の委任にも対応（監督は最終確認だけ、も可）
- **AI校（相手校）の自動採番**は `AiUniformNumbers` が単一ソース（`AiTeamBuilder` / `StrengthTeamFactory` 共通）:
  エース＝1／先発野手＝守備位置番号2〜9／**二番手投手＝10**／3枚目以降の控え投手＝11〜20の空き番号から
  (校ID, 年度) の決定論ストリームで2つ／控え野手＝残りを若い順。マウンド組の選手が守備で先発する日は
  守備位置番号（2〜9）が優先＝二番手投手が野手として出れば背番号も2〜9になり、**10はその下の投手へ繰り上がる**
  （番号は詰める。20人登録で10番が欠番になるのは不自然なので、順位でなく「控えに座った順」で配る）。
  結果として使う番号は常に1から連続し、欠番が出るのは登録人数が20人に届かないぶんの末尾だけ

### 3.4 試合
- 高速モード: スコアボード＋テキスト速報＋勝率インジケータ
- 詳細モード: **元祖踏襲の2ビュー構成**
  - 投打対決ビュー: 1球指示UI（ストライクゾーン図で配球・狙い球、作戦パネル）＋
    対決カットイン（デフォルメ静止画の紙芝居＋球速・球種・判定表示）
  - ~~打球が出た瞬間に**守備俯瞰ビュー**へカット（2D再生モックの本実装）~~
    → **2026-08-01 改訂（監督決定・打球処理の3D化）。打球が出ても3Dのまま**、
    本塁後方の**守備カメラ**へカットして捕球・送球・走塁を3Dキャラで見せる（design-18 §1）。
    カット時刻はそのまま**タイムラインの接触イベント**（対決ビューで見せたぶんの続きから）。
    2D俯瞰は削除せず「2D俯瞰（デバッグ）」トグルとして残す（同じ時計で並走）
- **走者の小ダイヤモンド（issue #595・実装済み 2026-08-12）**: 守備フォーカス中だけ、盤面の**右下**へ
  出す走者ドット＋塁の小さな図（監督決定B案）。守備カメラは球と野手に寄って追随するので**枠外の走者は
  原理的に映らない**＝「三塁で止まったのか本塁を狙ったのか」がカメラ側では解けない。画面固定の図で補う。
  - 描くのは**走者ドットと塁だけ**（打球・野手は描かない＝2D俯瞰の縮小版にはしない）
  - 出るのは `BeginFieldPlay` を通る**全ての守備フォーカス**（打球・盗塁・牽制・振り逃げ・捕逸）。
    **打席中（対決の寄り）には出さない**＝塁の在/不在は ScoreBug の塁ダイヤの担当で役割を重ねない。
    2D俯瞰（デバッグトグル）表示中も伏せる（あちらが走者も野手も打球も描いている）
  - 走者位置は3Dの走者と**同じ `PlaybackEvaluator.RunnerAt` を同じ時刻で**評価する
    （`DuelStageRig.CurrentRunnerDots()`）＝補間をUI側に書き起こさない
  - **アウトになった走者はその時点で消す**（2026-08-12 監督指示）。残すと生きている走者と区別が
    付かず、この図の目的（誰がどこまで進んだか）を潰す。3Dが走者を消さない（`respectHideAt: false`）のは
    「選手が空中で消える」のを避けるためで、丸トークンにその制約は無い
    - 判定は engine の純関数 `PlaybackEvaluator.IsRunnerOut` に集約する。**`HideAt` だけでは足りない**
      ＝`HideAt` は「塁で決着したアウト」（封殺・タッチ・憤死・牽制死・盗塁死）しか持たず、
      **飛球の捕球アウトは打者走者のレッグに載らない**（`TimelineBuilder` の
      `batterOut = Out && !IsFly`）。捕球アウトの確定時刻は判定イベント（`Label="打"` の `Out`）に
      だけ有るので、`HideAt` を持たない走者はそちらで補う
    - 逆に `HideAt` を持つ走者は `HideAt` だけで判定する。内野ゴロの一塁フォースは送球到達で確定し
      走者はその後も塁まで走り切る絵になる（issue #328①）ので、判定イベントを優先すると
      **塁に着く手前で走者が消える**
  - 球場座標[m]→箱のローカル座標の写像は engine の `MiniDiamondProjection` が単一ソースで、
    塁マスも走者ドットも同じ関数を通る＝塁に居る走者は必ず塁マスの上に乗る。
    箱は塁の外側に 5m の余白を持つ（一塁駆け抜け 3.5m が枠から出ないため）
  - 面は ScoreBug と同じ**黒島語彙**（`--sb-face` ＋インク枠。design-19）＝芝・土・空のどの背景でも沈まない。
    黒島は盤面に2つだけで、左上＝ScoreBug／右下＝これ、と対角に置く
  - 走者はアンバー（盤面ビューの色は状態コード＝UI原則②の本数制限の対象外）
- **選手能力ビューア（issue #602・実装済み 2026-08-12）**: タイム（クリック中断ポップアップ）から開く
  **両校の名簿モーダル**。左＝自校・右＝相手を同時に出し、打線9人・現投手・控えを行に、能力を
  ランクチップで並べる（監督決定A案）。［野手能力］［投手能力］のタブは**両校まとめて**列を入れ替える。
  - **相手校も数値まで全開示**する（見極め/Insight によるぼかしはしない）
  - **役割でゲートしない**（issue #93/#381）＝控えは1本の名簿で、誰が継投候補かはプレイヤーが決める
  - **読むだけ**＝`MatchProgression.SubstitutionOptions` を両チームぶん呼ぶだけで engine を変更しない。
    伝令を消費せず乱数も引かない＝開閉が試合結果に影響しない（不変条件#2。1球の合間に開いても不変で
    あることを `MatchProgressionSubstitutionTests` が digest で固定する）
  - 能力の列・並び・ラベル・スタミナ/球威の逆変換は `MatchAbilityColumns` が単一ソースで、
    **選手交代モーダルの能力比較も同じ表を引く**（名簿画面の `PlayerCompareTabs` は `DevelopingPlayer`
    前提で、相手校の選手は育成選手を持たないため試合中には使えない）
  - 一覧に**生値は添えない**（ランクチップのみ）。20行×11列に「チップ＋2桁」を並べると隣の列と
    くっついて1つの塊に見え、列がスキャンできなくなる（実測）。細かい差の比較は交代モーダルが担当する
  - 弾道は1〜5の**型の段**（優劣軸ではないのでランク色を付けない・issue #219）、球速は km/h の実寸
- 同一タイムラインを2つのビューが描き分けるだけなので、エンジン側の追加実装は**ほぼ**不要
  （表示専用の追加が2件だけ: 送球の投げ手／受け手 `FromRole`/`ToRole`/`ToBase` と、
  フレーミング定数の任意引数化 `CameraFraming`。どちらも乱数非消費・帯不変・既定は現行値）
- 画面中央は3Dビューに差し替え可能なコンテナとして設計 → **差し替え済み**
- ⚠ **判定オーバーレイ（アウト/セーフ/フェア/ホームラン）の器は盤面の外に置く**。

| §3.8 キャリア | **監督** | 付いてくる | 指導力・名声・歴任校・教え子名鑑 |
| §3.9 記録 | **学校** | 学校に残る | 年度別の大会結果・校歴代の個人記録 |

`SchoolRecordBook` は両タブが引く（キャリアは「監督の通算」、記録は「その学校の歩み」として出す）。

**画面内タブ（監督決定 2026-08-12・C案）**: ［歴代大会］［個人記録］を排他に切り替える。
1ページが全幅を使えるので個人記録を**3位まで**出せる。部品は既存の `SegTabs`（設計書16 §10.2 の
穴#10「TabBar」は新規部品を作らず SegTabs で足りた）。

- **歴代大会結果**は engine の `TournamentHistory` に年度ごとの1行（年度・大会種別・自校の到達ラウンド・
  優勝校）を積む。`SchoolRecordBook.FoldTournament` が**累計へ畳んで年度を捨てる**ので、年度別の記録は
  この台帳にしか残らない＝**セーブへ焼く**（v8）。積むのは大会終了時の1回だけで**乱数を消費しない**。
- **成績の文言**（「3回戦敗退」「準優勝」「優勝」）は engine の `TournamentResultLabel` が組み立てる。
  到達ラウンドは「決勝」でも優勝と準優勝の両方があり得るので、ラウンド名だけでは決まらない。
- **記録室の集計は engine の `RecordRoom`**（純関数・表示専用）。通算はキャリア通算（**練習試合を含む**・
  監督決定 2026-08-12）、シーズンは大会別アーカイブを「選手×学年」＝1シーズンへ畳んだもの。
- **規定打席・規定投球回**は `data/coefficients.yaml` の `records:`（チーム試合数×係数）。
  高校野球は試合数が少なく、閾値が無いと「1打数1安打＝打率1.000」が校歴代1位に出る。
  基準のチーム試合数は**選手の最大出場試合数**で代用する（チーム試合数のカウンタが無いため）。
  ホームのチーム内ランキングも同じ関数を引く＝閾値が2箇所に散らない。
- **シーズン記録の「年」は大会別アーカイブに焼いた年度から出す**（issue #600 で追加）。
  アーカイブのキーは学年×大会枠で年を持たず、卒業生は学年が3で止まるため暦年を逆算できない。
- **年は engine では年度（YearIndex）で持ち、暦年化は Unity 側の `SeasonClock`**（不変条件#3）。
- 含めないもの: 全国記録・他校の歴代（`NationTournamentStats` は大会切替で全消去＝今大会しか持たない）、
  1試合単位の記録（ボックススコアを試合後に捨てるため作れない）、記録更新の通知フィード連動。
- ⚠️ `PlayerStatStore` は「監督の手持ち」であって**学校に紐づいていない**。転任（§04 §1.2・未実装）が
  入ると他校の成績が校記録へ混ざる。分離は転任 issue で行う（本 issue では TODO のみ）。
  同じ理由で歴代大会結果の「大会名」の県も**いまの本拠県**から引いている。

### 3.10 イベント（ノベル提示・issue #609 で実装）

週次イベントの会話を見せる面。**タブではなくホームの本文域の入れ替え**（案B「トップバー残し・立ち絵中」・
監督決定 2026-08-13）。トップバー（暦・部費・ランク・ナビ）は残したまま、ヒーロー帯＋3カラムを
この面と `display` で二者択一する。

```
┌─ トップバー（そのまま残る） ────────────────────┐
├──────────────────────────────────────────────────┤
│ │今週の出来事                                     │
│            ┌──────────┐                          │
│            │  立ち絵   │  ← 役割スロット（単色）  │
│            └──────────┘                          │
│               コーチ                              │
│ ┌──────────────────────────────────────────────┐ │
│ │ コーチ                                        │ │
│ │ 監督、そろそろ切り上げますか。…               │ │
│ │ 1 / 3                          クリックで次へ │ │
│ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- **暗幕を敷かない**。昼NB（design-19）の白地に全画面の黒幕が乗ると別のゲームに見えるため、
  他のモーダル（`.tm-scrim`）とは作りが違う。面のどこを押しても次の行へ進み、最後の行で閉じる
  （**主要操作は面そのもの＝ボタンを置かない**。UI原則⑦）。
- **アクセントを1つも置かない**。会話に「今すぐ押すべき赤」は無い（応援団赤はCTA専用・UI原則②）。
- **立ち絵はまだ無い**。役割ごとの単色シルエット＋役割名のプレースホルダで、差し替え口は
  `EventPortraits` の1箇所だけ。地の文（`who: narration`）はスロットごと消す
  （空の枠を残すと「絵が抜けている」ように見える）。
- **話者名は明朝**（人名の書体規則・設計書16）、本文はサンセリフ、進捗「1 / 3」は Oswald。
- 会話は**発火時に確定済み**（設計書03 §5.3a）で、この面は選び直さない＝何度開いても同じ文。
- 同じ週に複数件出たときは続けて見せる。**新チーム発足・大会開幕バナーが出る週は後回し**にして
  キューに残し、次にホームへ来たときに出す（取りこぼさない）。

## 6. 共通トップバー規約（全画面共通・この先の決まり事）

画面上部の「スコアボード＋ナビ」は **`Assets/UI/Components/TopBar.uxml` を単一ソース**とする。
各画面で独自ヘッダーを作らない（過去に選手一覧が独自コンパクトヘッダーを持ち、上部UIが画面間で不一致になった。統一済み）。

**新しい画面を追加するときの決まり事:**
1. UXML 冒頭で `<ui:Template name="TopBar" src="Components/TopBar.uxml" />` を宣言し、ルート直下（**ScrollView の外＝固定トップ**）に `<ui:Instance template="TopBar" />` を置く。本文は別の ScrollView に入れる。
2. ナビのクリック導線とアクティブタブ強調は **`ScreenRouter` が自動配線**する（画面側で書かない）。ナビ項目名は `nav-home / nav-players / nav-training / nav-tournament / nav-scout / nav-management / nav-career / nav-records`。
3. スコアボードの動的値は各画面のコントローラが `name` で埋める:
   - `week`（現在日付）= **`GameClock.CurrentLabel()`** を必ず通す（画面ごとに書式を作らない）。表記は **「YYYY年M月W週目」**（年度1=2026年度・4月始まり。1〜3月は暦年+1）。週→暦の変換はエンジン `SeasonCalendar.DateOf`、暦年の起点は `SeasonClock` が正。
   - `team-rank` = 総合力ランクの等級チップ（`grade` + `grade--X`）。
   - `funds / fame / trust / countdown` 等はデータが無ければ TopBar 既定値のまま可（現状ホーム/練習も既定値依存）。
4. **現在週は全画面共有の `GameClock`（Shell層・セッション単一ソース）が持つ**。各画面の State は自前で週を持たず GameClock から読む。「今週を進める」(`advance`) はどの画面から押しても `GameClock.Advance()` で共有週を進め、**全画面の日付・合宿バナー・成長段階が連動**する。既定はシーズン頭（週0＝2026年4月1週目）で、Play開始（ドメインリロード）で週0へ戻る。
   ※ 部員データ等は依然として画面ごとに ephemeral（プロトタイプ）。共有するのは「現在週」だけ。
5. **一覧→詳細**の従属画面（選手詳細・試合・大会）は「戻る」動線が要るため、TopBar と戻るボタンの併存方式を後で確定する（**未決**）。現状これらは旧ヘッダーのまま。統一時はこの規約に寄せる。
