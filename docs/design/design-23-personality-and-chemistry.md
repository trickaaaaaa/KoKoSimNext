# 設計書23 — 性格の4軸×16タイプ・バッテリーの相性・チームの結束

> 状態: **確定（2026-11-14）**。未決事項 Q34〜Q40 は監督の回答で決着（§7）。
> 起点: issue #924。実装はこの設計書が確定してから、§6 の分割で別 issue にする。

## 0. 目的と範囲

- 選手の性格を、設計書01 §1.1 の**4つの傾向値**で持つ形に実装を追いつかせ、その組み合わせ（2値×4＝16）を性格タイプの名前にする
- 性格どうしの組み合わせで効く要素を2つ入れる: **バッテリーの相性**（投手×捕手）と**チームの結束**（部全体）
- 方針（2026-11-14 監督と合意）
  - MBTI は使わない（軸が野球の効き目に結びつかない・世界観・商標）。軸は設計書01の4つ、名前は独自
  - 16×16 の相性表は作らない。軸の値から**式で**出し、係数は `data/coefficients.yaml`（不変条件#4）
  - **効きは小さく**（設計書03「効果は小さな補正、根幹は数値管理」）。AI校も同じ仕組みで動かす
  - **見える形にする**（UI原則⑥）。ただし性格は隠し要素で、見極めで開示されるのは今のまま
- 範囲外（§5）: 二遊間などバッテリー以外のコンビの相性、性格の変化（性格は生まれつき固定のまま。設計書03 §3.3）

## 1. 性格の4軸

### 1.1 軸と値の持ち方

4軸とも **1〜99 の整数（50＝中立）** で持つ。既存の `Leadership`（統率傾向）と同じ形にそろえる。

| 軸 | コード名（案） | 高い側 | 低い側 | 現状 |
|---|---|---|---|---|
| ① 統率傾向 | `Leadership`（既存） | 引っ張る | ついていく | **既にある**（1〜99・平均50・σ15。性格タイプごとに平均をずらしている） |
| ② 素直さ | `Receptiveness` | 素直 | 頑固 | タイプ表の `coaching_receptivity` に埋まっている |
| ③ 勤勉さ | `Diligence` | コツコツ | 気分屋 | タイプ表の `self_growth_factor`（＋個体差 `PersonalityFactor`）に埋まっている |
| ④ 試合での姿勢 | `Selflessness` | 献身 | 目立ちたがり | タイプ表の `bunt_success_bonus` / `chance_hit_factor` に埋まっている |

- **性格タイプは4軸の値から導出するラベル**（各軸が50以上か未満かの2値×4＝16）。タイプを別に保存しない
  （投手役を属性で持たず導出するのと同じ考え方。design-01 §1.1a）
- 各軸の効き先は1つに固定し、二重計上しない（設計書01 §1.1 の原則をそのまま守る）

### 1.2 各軸の効き先（既存の効きを軸の式へ置き換える）

効きの**場所は今と同じ**で、タイプ表の値を軸の一次式に置き換えるだけ。新しい効き先は足さない（§2・§3 は別枠）。
`d = (軸の値 − 50) / 50`（−0.98〜+0.98）とする。

| 軸 | 効き先（今と同じ場所） | 式（係数は YAML。値は現行表の幅に合わせた初期値案） |
|---|---|---|
| ① 統率傾向 | 主将の統率力（design-09 §8）・伝令の係数（`TimeoutMessenger.FactorOf`） | **変更なし**（既に `Leadership` で効いている）。タイプ別の平均ずらし `leadership_mean_offset` は生成の分布（§1.4）へ移す |
| ② 素直さ | 指導の入りやすさ `CoachingReceptivity`（個別指導・伝令の落ち着き `PressureModel.CalmMultiplier`） | `1 + d × 0.11`（現行 0.88〜1.10） |
| ③ 勤勉さ | 自主成長 `SelfGrowthFactor`（`PersonalityFactor`） | `1 + d × 0.10`（現行 0.92〜1.10。タイプ内の個体差σ0.06 は軸の連続値が引き受ける） |
| ④ 試合での姿勢 | 犠打の成功 `BuntSuccessBonus`／チャンスの長打 `ChanceHitFactor` | 犠打 `d × 0.06`、チャンス `1 − d × 0.10`（現行 −0.06〜+0.05 / 0.97〜1.10） |
| （④＋①） | 伝令役の得意場面 `messenger_to_pitcher / to_batter`（#716） | 統率の分は `FactorOf` が既に `Leadership` で見ているので、ここでは④だけを見る: 献身は**投手へ**（寄り添う）、目立ちたがりは**打者へ**（盛り上げる）が得意。`to_pitcher = d × 0.06`、`to_batter = −d × 0.06` |

- 「内向的」が本番に弱い（`chance_hit_factor 0.97`）のは、現行では性格に埋めてあるが本来は精神力の役目。
  ④の式に寄せると「内向的」は献身側なのでチャンス係数は1未満になり、向きは保たれる
- 帯（統計回帰）との関係: 統計シムのチームは今も性格で能力が動く（`StrengthTeamFactory` が性格を引く）。
  **母集団の平均効果を現行と一致させる**ことを §1.4 の受け入れ条件にする

### 1.4 生成の分布と、強さがずれないことの確かめ方

- **今の出やすさを残す**（Q36 決着）。生成は2段: ①今の8タイプを `spawn_weight` で1つ引く（努力家・マイペースが多く、天才肌は少ない）
  ②そのタイプのマスの代表値を中心に、素直さ・勤勉さ・姿勢を正規分布（σ12案）で引く。①統率は今どおり `leadership_mean_offset` で平均をずらして引く
  - ばらつきで軸が50をまたいだ選手は隣のマスへ移る＝新しい8タイプ（花形・世話焼き等）は**既存タイプの少し外れた形として自然に少しずつ出る**
  - `spawn_weight` は残す（8タイプの代表値の表と並べて YAML に置く）
- **統計の帯は選手の生成を通らない**（`StrengthTeamFactory` / `ProspectGenerator` の変更に Heavy は安全網にならない）。
  そこで、生成した母集団の**平均効果が現行と一致する**ことをテストで固定する:
  - 現行（spawn_weight で加重した8タイプ）の母集団平均: 指導 1.0085／自主成長 1.0052／犠打 +0.0089／チャンス 1.0134／統率ずらし +0.8
  - 新しい生成（例: 1万人）の平均がこれと許容差内（指導・成長・チャンス ±0.005、犠打 ±0.003）
  - そのうえで Heavy を回し、帯内であることを確かめる（不変条件#5）

### 1.5 セーブの移行・見極め

- セーブは `personality`（8タイプの列挙）を持っている（`PlayerSaves.cs:40` / `DevelopingPlayerSaves.cs:69`）。
  移行は**旧タイプのマスの代表値**へ置き換える（例: 天才肌 → 素直さ35・勤勉さ65・姿勢35）。乱数は使わない（ロードのたびに同じ結果）
  - `Leadership` は既に個人の値を持っているので触らない。`PersonalityFactor` は勤勉さへ逆算する
  - 列挙 `Personality` は表示用ラベルの導出結果として残す（`Normal`＝全軸50の中立も残す。手組みの選手が無補正で動く安全弁）
- 見極め（`InsightModel`）は**軸ごとに開示**する（Q37 決着）。「素直な子のようだ」のように1軸ずつ判明し（誤認もあり得るのは今と同じ）、4軸そろうとタイプ名が出る

## 2. バッテリーの相性（優先）

### 2.1 何を表すか

同じ投手でも、**組む捕手によって**持ち味の出方が少し変わる。相性は2つの和:

- **出発点の相性** `S0`: 2人の性格から決まる（組んだ瞬間からある）
- **積み重ね** `B`: 公式戦で一緒に守ったイニングで育つ（固定バッテリーで育てるか、継投・併用で崩すか、という采配の悩みを作る）

### 2.2 出発点の相性 S0（式・係数は YAML）

`d①〜d④` は §1.2 の `d`。P＝投手、C＝捕手。

```
S0 = a1 × dC①                 # 捕手が引っ張るほど、誰と組んでも合わせやすい
   + a2 × dP②                 # 投手が素直なほど、捕手のリードを受け入れる
   + a3 × min(dP④, 0) × min(dC④, 0) × (−1)   # 2人とも目立ちたがり＝ぶつかる（負）
   + a4 × max(−dP④, 0) × max(dC④, 0)         # 目立ちたがりの投手 × 献身的な捕手＝女房役（正）
S0 は −1〜+1 に丸める
```

- 初期値案: `a1 0.35, a2 0.35, a3 0.30, a4 0.30`。母集団平均がほぼ0になる（強い捕手・素直な投手は平均では打ち消し合う）
- 勤勉さ（③）は相性に使わない＝自主成長だけに効かせる（二重計上しない）

### 2.3 積み重ね B（何を記録し、どこに保存するか）

- 記録: **投手ID×捕手IDの組ごとの、一緒に守ったイニング数**。公式戦は1、練習試合・紅白戦は**0.5の重み**で数える（Q38 決着。控えのバッテリーも練習試合で育てられる）
- `B = 1 − exp(−イニング数 / τ)`（0〜1）。初期値案 τ＝60イニング（エース級が1シーズン組んで0.7前後）
- 減らない。どちらかが卒業・転校したら消える
- 保存: **自校**はセーブに組ごとの記録を持つ（多くても数十組）
- **AI校**は組ごとの記録を持たず、「同じ学校で過ごした年数」から B を近似する（2人とも在籍していた年数×係数）。
  AI校のロスターは年をまたいで永続している（#80）ので決定論で出せる。効果の式は自校と同じ（Q39 決着）

### 2.4 相性の値と効き先

```
相性 K = wS × S0 + wB × B          # 初期値案 wS 0.5, wB 0.5 → K は −0.5〜+1.0
```

効き先は**既存の解決式を通す**ものだけにする（不変条件#1。表示の能力値を確率に直接使わない）:

| 効き先 | 経路 | 大きさの目安（K＝+1 / −0.5） |
|---|---|---|
| 捕手のリードの効き | `BuildAtBatContext` の `catcherLead`（`AbilityEffect.Pitching(Lead)` の結果）に `1 + k1 × K` を掛ける | k1 0.15 → リード実効 +15% / −7.5% |
| 動揺からの立ち直り | `TeamState` の `RattledRecoveryOuts` を K ≥ 0.6 で −1（2アウト→1アウト） | 段階的（乱数不使用） |
| ピンチの制球 | プレッシャー指数が高い場面だけ、`PressureModel.ApplyPitcher` に `1 + k2 × K × 圧の強さ` | k2 0.03 → 最大 +3%（チームの勢い #863 の最大 +6% より小さく） |

- 乱数を使わない（RNG列は不変。結果は効果の分だけ変わる）。試合結果の指紋（determinism-baseline）は変わるので再生成する
- 統計シムでは、生成した捕手×投手の S0 は平均でほぼ0、B は「同じ学校の年数」で決まる。帯への影響は Heavy で測る（不変条件#5）

## 3. チームの結束

### 3.1 値

結束 `U` は学校ごとの 0〜100（50＝ふつう）。2つの和:

- **顔ぶれから決まる土台** `U0`: 部員（ベンチ入りの20人）の性格から週ごとに計算し直す
- **出来事による上下** `ΔU`: 合宿・不和イベントなどで動き、週ごとに少しずつ0へ戻る

### 3.2 顔ぶれの土台 U0（式・係数は YAML）

```
U0 = 50
   + b1 × 主将の統率力（design-09 §8。主将がいなければ0）
   + b2 × 「引っ張る」側（①が65以上）の人数（上限3人まで数える）
   − b3 × max(0, 目立ちたがり（④<50）の割合 − 0.5)    # 半分を超えた分だけ
   − b4 × 一匹狼（①↓②↓④目立）の人数
```

- 主将の指名で結束が動く＝主将選びに「誰がまとめ役になるか」の判断が増える（#861 の指名画面に結束の見込みを出せる）
- 「チームの勢い」（#863）は**試合の結果**で上がるもの、結束は**人の顔ぶれと出来事**で決まるもの、と分ける。二重に効かせない

### 3.3 上下させる出来事（design-03 / design-04 の「結束」を実体化）

| 出来事 | ΔU（初期値案） | 出典 |
|---|---|---|
| 合宿（通常 / 強化） | +6 / +10 | design-04 §合宿 :436「結束↑ / ↑↑」 |
| 選手間イベントの好転（不和解消など） | +3〜+5 | design-04 :441・design-03 §5 |
| 不和・サボりイベントの悪化 | −3〜−6 | design-03 :163 |
| 主将の交代 | U0 の再計算で自然に動く | design-09 §8 |

- `ΔU` は週ごとに 10% ずつ0へ戻る（一度の合宿の効果が1シーズン持続しない）
- イベントの分岐の好転率に主将が効く仕組み（design-09 §8.1「チーム運営」）は、ここで結束を経由して実体化する

### 3.4 効き先（精神面の既存の仕組みに限る）

| 効き先 | 経路 | 大きさの目安（U＝80 / 20） |
|---|---|---|
| 動揺の起きにくさ | `RattledThresholdFor` に結束の段（U≥70 で +1、U<30 で −1） | 連続出塁の閾値 ±1 |
| 伝令の効き | `TimeoutMessenger.Factor` に `1 + c1 × (U−50)/50` | c1 0.10 → ±6% |
| 能力への直接の補正 | **しない** | 結束が打撃・投球の能力そのものを上げることはない |

- AI校は U0 だけを使い、ΔU は0（AI校には合宿・イベントが無い）。自校だけが ΔU で上げ下げできる＝監督の手腕の差（Q40 決着）

## 4. 見せ方（置き場所と出す情報だけ。レイアウトは実装 issue で ASCII 3案）

## 5. 範囲外（後回し）

- 二遊間の併殺の速さ、外野の連携、主将×各選手の相性などの「コンビの相性」
- 性格の変化（性格は生まれつき固定。設計書03 §3.3 の方針のまま）
- 結束が練習効率に効くこと（育成のバランスに触れるので、B・C が動いてから別に検討）
